# Scene editing contract: clips, playback order and timing

This bounded extension uses the existing Streamlit Scene Editor, scene plan,
generation manifest and MoneyPrinter composer. It does not select a new editor
framework or project interchange format.

## Asset and timing contract

- A replacement is an explicitly uploaded MP4, at most 100 MiB. The upload's
  filename and original host path are never persisted. Task and scene IDs must
  resolve to an existing task and scene before files are written.
- The clip must decode, match the scene aspect, and cover its generation target
  and any longer saved playback duration. FFmpeg trims from the selected start,
  normalizes to H.264/yuv420p and removes audio. There is no speed change,
  looping or new narration.
- Only validated media becomes a new `generated_ai/scene-NNN/vNNN.mp4` version.
  Existing versions remain available under the normal cleanup policy.
- Additive version metadata records `asset_origin=imported` and
  `import_metadata.media_sha256`. Missing origin means `generated` for existing
  manifests. Generation settings remain the scene's regeneration recipe, not
  a claim that the uploaded media was generated by that provider. Public
  material provenance identifies imports as `manual_upload`.

## Change impact and recovery

| Action | Video inference | Narration/captions | Composition |
| --- | --- | --- | --- |
| Replace clip | None | Reuse | Rerender |
| Reorder visuals | None | Reuse at existing audio/caption times | Rerender |
| Restore generated/imported version | None | Reuse | Rerender |
| Prompt/seed regeneration | Selected scene only | Reuse | Rerender |
| Existing render-only changes | None | Reuse | Rerender |

Replacement does not change `scene_plan.json`, the script or task settings.
Render failure rolls back the active manifest and prior final/combined outputs.
Successful edits refresh material provenance and the existing artifact index.
They never submit a publishing job.

Resume revalidates imported clips, including their content hash, using generic
media validation rather than a model-specific output validator. Imports remain
selected across model fingerprint changes, provided the scene identity,
narration segment, aspect and target duration still match. A missing, damaged
or incompatible import blocks Resume with guidance to replace it or restore a
valid version. It is never silently substituted with AI footage. Explicit
regeneration switches the new active version back to generated provenance.

## Acceptance

CPU fixtures must exercise real media normalization and composition, version
restore in both directions, restart/Resume with mixed generated/imported clips,
invalid upload rejection, checksum failures, render rollback and queue failure.
Assertions must cover no video/TTS/caption/BGM generation on replacement,
unchanged unrelated scenes/audio/captions, safe task-local paths and truthful
provenance. Existing provider/recovery/cleanup regressions must remain green.

## Visual playback order

The next accepted extension adds **Move earlier / Move later** to the same
Scene Editor. `generation_manifest.json` may contain an additive top-level
`playback_order` list of stable scene IDs. It must contain every scene ID
exactly once. Existing manifests without the field use ascending scene-ID
order, with no migration or scene fingerprint change. Invalid saved orders
block composition/Resume before inference rather than being silently repaired.

Scene IDs, generation order, scene-plan narration segments, target durations,
version paths and active selections stay unchanged. Only visual playback order
changes. Each clip keeps its existing duration under the existing composition
settings; this milestone introduces no trim, speed or duration controls.
Narration and captions keep their existing timestamps. Consequently footage
can accompany different words and visual cut times may move when clips have
different lengths. The editor explains this explicitly. Moving narrated scenes
together requires a separate audio-segmentation/retiming milestone.

All composition paths use the saved order, including Resume, regeneration,
replacement, restore and render-only rerender. Provenance and artifact-index
scene-material lists follow playback order while retaining stable scene IDs.
Reopening the editor displays saved playback positions alongside those IDs.
Generation/provider fingerprint checks remain independent of playback order.

The serialized WebUI worker rejects busy/publishing tasks and stale order
requests. A move queues a render-only transaction using saved narration,
captions and existing generated BGM, with no LLM, video/TTS/caption generation
or publishing call. Invalid media or failed composition restores the previous
manifest and all final/combined outputs. A no-op order does not rerender.

Acceptance includes a three-scene real-media export with verified color
sequence, unchanged audio/captions/scene versions, restart and cached/partial
Resume, provider fingerprint changes, imported/versioned scenes, render
rollback, stale/invalid orders, queue failures and the Streamlit controls.

## Fixed-duration clip trims

The Scene Editor now accepts **Clip start (seconds)** for a new MP4 upload or
**Trim saved clip** for the current active version. The cut keeps the scene's
existing target duration, saved playback order, narration and caption times.
The selected start must be finite and non-negative. Insufficient remaining
footage fails validation; no stretching, looping or frame padding is added.
An upload still has the existing 100 MiB bound. Saved clips use the same bound.

Trims materialize a new video-only, task-local version through the existing
replacement transaction. Older versions remain restorable under the existing
cleanup policy. `import_metadata.start_seconds` records the source-relative
start. A saved-clip trim additionally records `operation=trim`, the task-relative
`source_asset`, its hash and `source_origin`. Material provenance labels this
operation `scene_trim`, rather than claiming a new model call or manual upload.
The existing `asset_origin=imported` validation category deliberately protects
these edited clips from model-fingerprint invalidation and checks their saved
media hash during Resume and restore. Generation recipes remain unchanged.
The active trim is self-contained; its source reference is provenance and does
not require retaining that old version forever.

Submission and the worker both bind saved trims to the expected active version.
Media decoding stays in the serialized worker. Stale versions, busy/publishing
tasks, missing required captions and damaged imported sources are rejected.
Render failure restores the previous manifest and final/combined outputs.
No provider, narration, caption, music-generation or publishing call is added.

Saved versions contain only the footage already persisted. Earlier imports
were normalized to scene length and discarded excess footage, so they often
have no room for a later start. Upload the longer original again and select its
start time before replacing. This milestone does not retain raw uploads,
change timeline lengths or move narration with visuals.

## Visual cut timing with a fixed audio track

**Screen duration (seconds)** and **Apply timing with next scene** move one
visual cut. The following scene in saved playback order balances the difference.
The last scene has no following scene and is edited through the preceding cut.
**Reset scene timing** removes the override and restores the original composer
behavior. Narration, caption timestamps, total planned visual duration, clip
versions and generation recipes remain unchanged. Moving a visual cut can
change which spoken words that footage accompanies.

The additive top-level `playback_durations` object maps every stable scene ID
(as a string) to positive finite seconds. Its sum must match the sum of original
scene targets within 1 ms. There is no migration for older tasks; absent timing
metadata preserves their existing composer behavior. Timing values follow scene
identity when reordered, and remain separate from scene fingerprints and version
history. Invalid saved maps fail before inference during Resume. Provenance adds
`playback_duration` only while timing overrides are active.

Timing overrides use normal speed and sequential playback. They replace the
shared clip-duration cap for this task's local-AI composition. Every selected
source must contain enough footage. The composer rounds cumulative cuts to the
output frame grid so rounding does not accumulate across scenes. It rejects
sub-frame slots and unavailable footage rather than stretching, looping,
skipping a failed scene or silently repairing timing. The total visual budget
must cover the recorded narration; final export still ends at narration length.
Existing non-timing and non-local-AI composition behavior is unchanged.

The serialized worker rechecks order, duration values and active versions from
an immutable submission snapshot. Busy/publishing tasks, stale requests and
missing required captions are rejected. The timing transaction backs up and
restores the previous manifest and final/combined outputs on failure. No LLM,
video, TTS, caption, generated-music or publishing request is made by a timing
edit. Resetting also uses the same transaction.

Reopening, cached/partial Resume, reorder, render-only rerender, replacement,
trim and version restore retain the override. New uploads and trims retain at
least the longer of the generation target and playback duration. Explicit
regeneration and model-change Resume still follow their existing generation
recipes. If a resulting clip cannot cover an extended playback slot, composition
fails explicitly; restore a longer version or reset timing. Increasing a model's
requested generation length automatically is outside this milestone.

Acceptance covers exported cut positions, unchanged audio/captions/assets,
frame rounding, restart and partial Resume, replacement/restore/reset,
no inference on timing edits, malformed and stale requests, queue failures,
insufficient footage, render rollback and the Streamlit controls. Independent
narration/caption editing and changes to overall video length remain deferred.

## Estimated narration ranges and offline previews

**Prepare narration previews** explicitly creates `narration_ranges.json` and
short task-local PCM WAV previews from existing narration. Each stable scene ID
receives a saved start/end range. The initial ranges divide the measured decoded
audio length by the original scene-duration weights, in ascending scene-ID
order. They are labelled **estimated**, with `speech_aligned=false`; they do
not prove where a sentence was spoken. No alignment model, TTS, transcription,
video inference, final composition or publishing is called.

The separate sidecar records the exact source audio hash, task-relative audio
reference, script hash, scene IDs/text, initial estimation weights, measured
sample duration and range/preview hashes. It is deliberately separate from
visual playback order, screen durations, prompts, seeds and generated versions.
Reopening and Resume preserve it; visual reorder, retiming, replacement and
restore do not rewrite the ranges. The output package/API optionally indexes
the sidecar as `narration_ranges`.

Preview preparation runs in the existing serialized WebUI queue. It restores
the prior completed or failed task status; preparing previews never makes a
failed video task successful. Busy/publishing tasks are rejected. No Voice's
silent timing track is excluded, while custom recorded audio takes precedence.
Audio must be task-local. This first preview slice bounds work to 512 scenes
and one hour of audio, with fixed 16 kHz mono PCM preview output and bounded
FFmpeg calls. A temporary decoded track avoids MP3 encoder-padding errors and
is removed before publication; source audio/captions/video remain unchanged.

A valid saved map and previews are reused without rewriting. Explicit preparation
after changed audio, script or scene narration creates a new estimated map.
Damaged/missing previews are rebuilt using the same saved ranges when source
bindings still match. Extraction or atomic-write failure preserves the prior
sidecar and active preview set. Successful publication removes inactive owned
preview sets, keeping storage bounded. All persisted references are task-relative.

**Preview narration** validates source identity, range coverage, scene binding,
preview checksum and decoded duration before serving an actual cut WAV. The UI
keeps at most one preview cached and clears it when source/plan/script/sidecar
files or the selected audio change. Saved range labels may remain visible until
explicitly rebuilt, but changed sources cannot load old audio previews.

Acceptance includes two-tone audio cut content/duration, MP3 padding, saved
range persistence across visual edits and full restart/partial Resume, stale
source rejection, damaged-preview recovery, extraction/publication rollback,
No Voice/custom audio, path bounds, queued errors/status restoration, artifact
serialization, and estimate-labelled Streamlit playback. This remains a
read-only narration foundation: text/audio edits, verified speech alignment,
caption rebuilding and downstream retiming are later milestones.

## Operator-adjusted narration boundaries and review

The next bounded step adds **Narration boundary end (seconds)** and **Apply
narration boundary**. The chosen end also becomes the following narration
range's start, in original narration/scene-ID order, independently of visual
playback order. The audio starts at zero and the final endpoint remains fixed.
Boundaries must be finite, sample-rounded and leave non-empty audio on both
sides. The last range's start is changed through its preceding boundary.

A successful change sets `basis=operator_adjusted` and rebuilds the preview set
from the same source audio. It never modifies source audio, captions, script,
visual timing, generated clips or final exports. `speech_aligned` remains false.
Original estimation weights are retained for traceability. **Mark range reviewed
after listening** records an explicit user assertion in the optional
`operator_reviewed_scene_ids` list; it does not run a model or independently
verify spoken words. The UI labels adjusted ranges and operator reviews
separately from initial estimates.

Moving a boundary clears reviews on both adjacent ranges. Other reviews remain
valid for the unchanged source. Preparing changed audio/script/scene narration
rebinds the map, restores initial estimates and clears previous reviews.
Reopening, ordinary preview preparation, damaged-preview recovery, Resume and
visual edits retain valid manual adjustments and reviews.

Actions use the serialized narration-preview queue and preserve prior task
success/failure status. Both submission and worker reject stale sidecar
revisions; publication also rechecks the revision after extraction. Source
bindings must still match. Failed extraction or publication retains the prior
map and active previews. A no-op boundary does not rewrite the map. User review
updates metadata without decoding or generating speech. No TTS, transcription,
video inference, final composition or publishing call is introduced.

Acceptance covers real cut durations, adjacent continuity, review invalidation,
invalid/final endpoints, source rebinding, no-op and stale requests, immutable
queued requests, failure rollback, persistence and UI controls. Actual narration
replacement/text edits, caption rebuilding, automatic alignment and downstream
retiming remain future work.

## Replacement narration drafts for audition

After preparing previews, listen to the original range and mark it reviewed.
Upload a WAV, MP3 or M4A file with **Replacement narration**, then choose
**Save narration draft**. **Preview narration** still plays the original;
**Preview narration draft** plays the upload. **Remove draft / use original**
discards the draft. The UI labels drafts as audition-only: exports, rerenders
and Resume continue to use the original master narration and captions.

Uploads are bounded to 20 MiB and decoded locally to 16 kHz mono PCM WAV.
Decoded duration must match the saved range within 2 ms; compressed-container
padding can cause a file to be rejected. No stretching, padding or trimming is
used to make a mismatched recording fit. WAV is useful for exact-duration edits.
The original review attests only to the selected source boundaries; it does not
validate the replacement's words or factual accuracy. No TTS, transcription,
caption, video, final-composition or publishing request occurs.

Each range may add an optional `replacement` object in `narration_ranges.json`,
containing only `preview_asset` and `preview_sha256`. Paths are restricted to
`narration_replacements/<UUID>/scene-NNN.wav`; source filenames/host paths and
raw uploads are not retained. There is one active draft per range. A new draft
is decoded and checked before atomic sidecar publication. Failed processing or
publication preserves the prior draft/map. The serialized queue snapshots the
request, rejects stale revisions and rechecks source binding before publication;
it preserves the prior completed/failed task state.

Reopening, preview repair, visual edits and same-task Resume preserve drafts.
Source audio/script/narration changes require explicit preview preparation and
clear old drafts. Remove drafts on both sides of a boundary before moving it;
the service rejects a boundary move that would invalidate an adjacent draft.
After successful publication, inactive owned draft directories are removed,
including interrupted upload/decode folders on the next preparation/save.
Changed or missing draft files fail preview validation; originals stay available.
This adds saved replacement auditions only. Applying edits to the master track,
text/TTS editing, caption rebuilding and downstream retiming remain deferred.

## Apply replacement recordings to exports

For an existing **creative** AI-video task, **Apply narration drafts and
rerender** now creates an edited narration track and exports existing footage
with that track. First tick **I want to export edited narration without
captions**. Old caption timing cannot be assumed valid for a new recording,
even when its duration matches. This milestone deliberately omits captions
from edited exports; it does not regenerate or validate spoken words. Factual
tasks reject apply until an appropriate edited-content review path exists.

**Restore original narration and rerender** switches exports back to the
original track and saved caption settings. The master narration, caption file,
script, scene plan, scene versions, visual order and screen timings are never
rewritten. Drafts remain available after restore. While a mix is active,
restore before changing drafts or boundaries. Preview original/draft controls
still audition their respective recordings. Source changes invalidate active
mix use; restore can recover even from damaged mix metadata.

The separate `narration_mix.json` records a schema version, source binding,
range/draft signature, task-relative mixed WAV reference/hash and
`captions_omitted=true`. Audio lives under
`narration_mixes/<UUID>/audio.wav`. Mixing uses the original decoded 16 kHz
mono PCM timeline and only substitutes selected ranges. The existing 2 ms
upload tolerance is normalized at the replacement tail (at most 32 samples)
so later samples do not shift. This does not support variable-duration edits,
text/TTS rebuilding, automatic speech alignment or caption rebuilding.

Apply/restore use the serialized narration queue with immutable range and
scene snapshots. The worker rechecks sources and scene versions/order/timing.
New mix media is staged before atomic active-metadata publication. Rendering
backs up previous final/combined outputs and restores them and previous mix
metadata on failure. Successful apply cleans inactive owned mix directories.
A process kill between metadata publication and render completion is not a
multi-file atomic transaction: rerender or restore can rebuild exports from
saved original/draft/mix assets after restarting.

The shared local-AI composer validates active mix inputs/hash on every later
render, including visual edits, render-only rerender and same-task Resume.
Stored generation recipes and source audio remain original. Output-package/API
fields `narration_mix`, `edited_audio` and `captions_omitted` distinguish the
edited audio from retained original `audio`/`captions` references. Invalid mix
media is never silently replaced with another recording. No LLM, TTS, video
inference, caption generation, paid BGM generation or publishing is triggered
by apply/restore. Existing generated BGM is reused.

## Complete creative narration/caption workflow (fixed timeline)

This milestone completes the existing **fixed-duration creative AI-task**
narration workflow in Scene Editor. It does not add a variable-length timeline
or extend the scene editor to stock-material tasks.

1. Prepare narration previews. Adjust the boundaries and mark each range
   reviewed after listening. Original narration order stays independent of
   visual playback order.
2. Enter **Replacement narration text / recording transcript** for a scene.
   Choose **Generate scene speech** to use the task's saved voice/rate and the
   existing MoneyPrinter TTS dispatch. Or upload WAV/MP3/M4A with its transcript.
   **Save recording transcript** updates text for an existing recording; it
   does not synthesize different words. Use Generate again to change speech.
3. Optional **Fit recording to this range** uses FFmpeg's pitch-preserving
   tempo adjustment, restricted to 0.5x–2x. Audio is normalized to the exact
   slot's sample count, including tail padding/trimming. Outside that range,
   shorten/extend the text or explicitly adjust boundaries first. With fitting
   off, the previous 2 ms duration-match rule remains. Preview the fitted draft
   before applying. Later ranges and video length never shift.
4. Check the recording transcripts and all range boundaries. Keep **Rebuild
   scene captions** selected and confirm the review checkbox, then **Apply
   narration drafts and rerender**. Rebuilding requires every range reviewed
   and a non-empty transcript for every replacement. Captions use one SRT cue
   per non-empty reviewed narration range; pause tags are excluded from visible
   captions. Existing styling is retained with sentence-level display.
   Disable rebuilding to retain the explicit caption-free export option.
5. The result uses existing visuals/music and the edited audio/captions.
   **Restore original narration and rerender** restores the master audio and
   original caption settings. Restore before editing active draft inputs.

Range review and transcript confirmation are operator assertions. This workflow
neither transcribes uploaded speech nor verifies that supplied words were
spoken. It does not promise automatic or word-level alignment. Generated TTS
may use the operator's configured external/paid speech provider when explicitly
requested; apply/restore do not call TTS, an LLM, Whisper, a video provider or
publishing. Scene TTS requires a saved non-No-Voice speech voice. Custom-recording
tasks with No Voice selected can edit by uploading recordings; pure No Voice
silent-timing tasks remain excluded from narration ranges. Saved voice/rate
are reused, but ephemeral voice-cloning reference inputs are not reconstructed
from old tasks; upload a finished recording when those inputs are required.
Factual-task apply remains blocked until edited-content review is separately
implemented.

### Persistence and transaction contract

`narration_ranges.json` remains schema version 1. A replacement optionally adds
`text`, `origin` (`upload`/`tts`) and `fit_ratio` to its existing WAV reference
and hash. Text is normalized, limited to 2000 characters and rejects control
characters. Metadata writes are limited to one MiB. Existing drafts without
text remain readable and usable in caption-free mode; add a transcript before
rebuilding their captions.

Captioned active mixes use `narration_mix.json` version 2 and stage `audio.wav`,
`captions.srt` and an edited `script.json` in the same owned UUID directory.
The original root script/audio/captions are never rewritten. The metadata
records hashes, source/range/draft bindings, operator transcript confirmation,
`timing_basis=operator_reviewed_ranges`, `speech_aligned=false` and
`captions_omitted=false`. The edited script records the full changed text and
range segments, retaining pause tags as script controls. The output package/API
adds `edited_captions` and `edited_script`; original references stay available.
Version 1 caption-free mixes continue to work without migration.

All actions use the existing serialized queue with immutable request snapshots.
TTS output stays in a temporary task-local directory, is validated before draft
publication and is removed on success, provider failure, fitting failure or a
stale revision. New captions/script/audio are staged before active publication;
rendering failures restore previous outputs and active metadata. Every later
local-AI render—including visual changes, rerender and same-task Resume—checks
all active audio/caption/script hashes and source bindings. Changed or missing
assets fail explicitly. Restore recovers the original track/caption settings.

The previous documented process-kill limitation still applies: active metadata
and multiple MP4 files are not one filesystem-wide atomic transaction. Saved
originals/drafts and validated active assets support rerender/restore recovery.
Variable-duration narration, independent caption timeline editing, automatic
speech alignment and factual edited-content review remain separate milestones.


Edited WAV, SRT and script JSON downloads are available directly in **Task
Manager → Artifacts**, with bounded file reads and checksum checks. Resetting
removes these active edited references and returns to original artifacts.
Regenerate still starts from the original generation recipe; use the downloaded
edited script if you want its changed text in a new task.

## Independent caption editing

Creative AI tasks now have an **Independent Caption Editor** below the existing
Scene Editor. It supports caption text and start/end edits, splitting a cue with
two supplied texts, merging with the following cue, adding a cue in a gap and
removing cues. These actions affect a saved draft only. Narration text/audio,
scene prompts, clips, generation recipes and original captions stay intact.

1. Open the task's Scene Editor and choose **Prepare / refresh caption draft**.
   It copies the current original or active narration-generated SRT into an
   independent draft. A task without captions starts empty. Valid existing
   drafts are retained; changed sources require explicit preparation to rebase.
2. Select a cue and edit its text or times in seconds. Save before making a
   different timing operation. Split uses the selected cue's saved boundaries
   and the two text fields. Merge concatenates the following cue with a line
   break and spans both cues, including any gap. Add sorts the new cue into
   time order. Invalid overlaps, out-of-range times or empty cues are rejected.
3. **Preview Caption Draft** queues a real MP4 from the saved first combined
   video, current narration and saved caption style. It leaves published final
   and combined videos unchanged. Background music is omitted from this preview;
   the label explains this. Existing combined video is required. The cue table
   and draft SRT download are also available without rendering a preview.
4. **Apply Captions And Export** rerenders with existing visuals, audio and
   saved music. The active caption track takes precedence over original and
   narration-generated captions. Cues are rendered at their manual times with
   sentence-level display and existing global caption styling. Editing a draft
   after applying does not change exports until Apply is chosen again.
5. **Restore Base Captions** removes only the independent active track and
   rerenders the current original/narration-generated captions with their saved
   enabled setting. Drafts remain available. Removing every cue and applying
   deliberately exports without captions. Task Manager Artifacts downloads the
   active SRT separately from the preserved original captions.

Cues use integer milliseconds, positive lengths, chronological order and no
overlap. Gaps are allowed. Bounds are the current recorded/silent timing audio
(up to one hour); at most 2000 cues, 2000 characters per non-empty plain-text
cue and one MiB per JSON/SRT file are accepted. Blank text lines, control codes
and markup delimiters are rejected. This does not perform speech recognition,
word alignment, factual review, scene-specific caption styling or a frontend
replacement. Factual and stock-task caption editing remain outside this slice.
Explicit No Voice timing tasks can use captions without generating speech.

### Caption persistence and change impact

`caption_edits.json` stores schema-version-1 draft cues and their binding to the
original/effective audio and base captions. `caption_track.json` stores an
independent active snapshot plus the task-relative SRT reference/hash under
`caption_tracks/<UUID>/captions.srt`. Active use validates source identity,
duration, cue bounds, canonical SRT bytes and hashes. Draft changes do not
invalidate an already applied active snapshot. Reordering visuals, scene edits,
render-only styling changes and same-task Resume retain the active captions.
No TTS, Whisper, video model, publishing or new paid-music request is made by
caption preview/apply/restore; export reuses existing generated music.

`caption_preview.json` binds a preview under `caption_previews/<UUID>/` to the
exact draft revision, source binding, combined-video hash, scene snapshot and
render settings. A changed draft, narration, footage or style invalidates it.
Success cleans inactive owned preview/track directories; failed preview work
keeps the last good preview. Artifact/API fields `caption_edits` and
`caption_track` index the optional sidecars. `edited_captions` points to the
validated independent SRT while that layer is active.

New narration mixes require restoring independent captions first so they cannot
silently reuse old timing. **Restore Original Narration** also removes an active
independent caption layer bound to the mix, returning to original audio and
captions together. Both layers and prior rendered videos roll back if that
restore fails. This recovery also works for damaged narration-mix metadata.
Drafts survive and can be explicitly rebased afterward.

Actions use the existing serialized task queue with copied requests, source and
revision checks, busy-task exclusion, scene snapshots for preview/apply/restore,
and late validation. Caption-only draft/preview actions retain prior task status.
Apply/restore stage assets before atomic metadata publication and preserve prior
metadata and final/combined videos on in-process rendering failure. As with the
existing narration workflow, publication across multiple MP4s and sidecars is
not one filesystem-wide transaction across process termination. Saved sources
and validated active assets support rerender/restore recovery after restarting.

CPU acceptance uses real MP4 composition and fake video fixtures, offline audio,
Streamlit controls, queue/status checks, invalid/stale-input and rollback cases,
No Voice/factual boundaries, and partial Resume with active natural narration.
Manual operator acceptance and real-GPU testing remain deferred.
